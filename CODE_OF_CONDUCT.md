# Code of Conduct

English | [简体中文](CODE_OF_CONDUCT_ZH.md)

## Our commitment

We are committed to making participation in Codex Relay a respectful, safe, and constructive experience for everyone, regardless of age, body size, disability, ethnicity, gender identity or expression, level of experience, nationality, personal appearance, race, religion, sexual identity and orientation, or socioeconomic status.

We act with particular care around session data and security reports. Prompts, source code, credentials, filesystem paths, and private conversations must never be exposed to make a point in a public discussion.

## Expected behavior

Examples of behavior that strengthens this community include:

- Being respectful, patient, and specific in technical discussions.
- Assuming good intent while evaluating claims by evidence.
- Giving actionable feedback about code or ideas rather than attacking people.
- Acknowledging mistakes, correcting them, and helping repair their impact.
- Respecting privacy, disclosure embargoes, and requests for anonymity.
- Keeping issues and pull requests focused on the project.

## Unacceptable behavior

Unacceptable behavior includes:

- Harassment, threats, stalking, discriminatory language, or unwanted sexual attention.
- Trolling, personal insults, sustained disruption, or publishing another person's private information.
- Sharing credentials, private session contents, security reproductions, or backup data without explicit authorization.
- Pressuring reporters to disclose a vulnerability publicly before a fix is available.
- Retaliation against anyone who raises a good-faith concern.
- Any conduct that would reasonably be considered inappropriate in a professional setting.

## Scope

This Code applies in project-controlled spaces, including issues, pull requests, discussions, reviews, and other official communication channels. It also applies when someone publicly represents the project or its community.

## Reporting and enforcement

For ordinary moderation concerns, contact the repository owner through a private contact method listed on their GitHub profile. For a concern involving a security vulnerability or sensitive session data, follow [SECURITY.md](SECURITY.md) and use GitHub's private vulnerability reporting flow.

Do not post sensitive evidence publicly. Include links, dates, and a concise description of the behavior, but redact credentials and session content.

Maintainers will review reports in good faith, protect the reporter's privacy where possible, and apply a response proportionate to context and impact. Possible responses include a private correction, content removal, a warning, temporary restrictions, or a permanent ban from project spaces.

Project maintainers who do not follow or enforce this Code consistently may be removed from moderation responsibilities.
