操作账本

每次迁移和恢复都保留独立备份、SHA-256 清单与哈希链事件。

迁移改变什么

工具只修改所选会话 rollout 中的 session_meta.payload.model_provider，以及 Codex SQLite threads.model_provider。它不会复制或修改 provider 凭据、API Key、OAuth 登录、config.toml 或模型设置。

并发写入

正在运行的 Codex 会继续写入 session。检测到 writer lock 时迁移会被阻止；仍建议先完全退出相关 Codex 任务。

兼容性

目标 provider 可能不支持原会话使用的模型、Responses API、工具调用、图片输入或 reasoning effort。迁移只影响会话可见性，不保证可继续推理。

版本变化

Codex 的本地存储不是稳定公开接口。升级 Codex 后应先预检；无法识别的数据库结构会停止操作，而不是猜测写入。

恢复限制

恢复前会比对迁移完成时的哈希。只要 Codex 又写过这些文件，恢复就会被阻止，防止覆盖新消息。此时应从备份人工合并。

备份敏感性

rollout 可能包含提示词、文件路径、工具输出和代码。备份目录权限受限，但仍应像源代码和聊天记录一样保护，不要上传到公共仓库。

进程崩溃

写入采用同目录原子替换，SQLite 使用事务。任何捕获到的失败会自动回滚；若机器断电，可在操作账本中找到写入前完整快照。

恢复迁移前状态

恢复会先备份当前状态，再用该操作的原始快照覆盖。若当前文件哈希已变化，系统会拒绝恢复。
